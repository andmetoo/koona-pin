# Технические и продуктовые решения

Записи по формату из [шаблона задачи](task-template.md#запись-технического-решения). Новое решение добавляется в конец; отменённое не удаляется, а помечается ссылкой на заменившее. Решения, которые ещё предстоит принять, оформлены задачами `decision` (индекс — [issues/README.md](issues/README.md)).

## Р-1. Платформы и порядок выпусков

3 октября 2026 года.

**Контекст:** нужен первый публичный выпуск без одновременной поддержки трёх ОС и телефонов.

**Решение:** Windows → macOS → Linux → Android → iOS. Первый публичный выпуск — Windows-beta со всем редизайном итерации 1 и захватом из Chrome, Edge и Firefox. Синхронизация появляется после desktop-портов и до мобильных выпусков. Локальное ядро бесплатно и работает без аккаунта; платные сервисы (синхронизация) — позже. Офлайн-копии страниц, режим чтения и ИИ-функции вне обязательного плана.

**Последствия:** ранний эксперимент с другими платформами (NP-008) ищет только архитектурные блокеры. Мобильные сценарии опираются на синхронизацию, поэтому её проектирование предшествует Android.

**Повод пересмотреть:** блокер Tauri на mobile, обратная связь beta, которая требует телефон раньше Linux.

## Р-2. SQLite остаётся единственным хранилищем

3 октября 2026 года.

**Контекст:** возник вопрос, не заменить ли SQLite лёгкой NoSQL-базой: текущий поиск медленный, а данные нельзя терять.

**Замер.** [`scripts/search-bench`](../scripts/search-bench/src/main.rs), та же сборка SQLite 3.46 (rusqlite 0.32 bundled), синтетическая библиотека с русскими и английскими словами, медиана прогонов на рабочем ПК:

| Способ | 10 000 закладок | 100 000 закладок |
| --- | --- | --- |
| Текущий `db::get_bookmarks`: все строки, запрос тегов на каждую, подстрока в Rust | 90 мс | 2 207 мс |
| FTS5 `trigram` (подстрока), общее число + страница 100 с тегами | 2,4 мс | 28 мс |
| FTS5 `unicode61`, префикс слова | 0,9 мс | 12 мс |

Под запрос подходила почти половина записей — это худший случай; реальные запросы избирательнее. FTS5 нашёл ровно те же записи, что текущий поиск, свернул регистр кириллицы и нашёл подстроку в домене. Встроенные `LIKE` и `lower()` SQLite кириллицу не сворачивают: `'%архитект%'` нашёл 0 записей вместо 1 030. Ни один индекс не приравнял «ё» к «е».

**Варианты:**

1. Оставить SQLite, исправить запросы и добавить FTS5.
2. Встраиваемое хранилище «ключ — значение» (redb, LMDB, RocksDB). Надёжны, но полнотекстового поиска, связей, уникальности и миграций нет — всё это пришлось бы писать вручную.
3. Встраиваемая документная база. sled официально в beta без стабильного формата файла; Realm свёрнут MongoDB; SurrealDB и PoloDB молоды для роли единственного хранилища личных данных.

**Решение и причина:** вариант 1. Медленным был способ запроса, а не SQL. Данные реляционные: закладки ↔ теги, коллекции, уникальность URL, атомарные массовые действия, корзина. SQLite — проверенное хранилище с транзакциями и стабильным форматом файла, встроено в Android и iOS, на нём построены готовые решения синхронизации.

**Последствия:** NP-011 переводит выборку на FTS5 со свёрткой ё/е и выдачей страницами; NP-012 добавляет виртуализацию, потому что следующим узким местом станет отрисовка тысяч карточек.

**Проверка:** повторить замер на реальной схеме в NP-011; ориентир p95 поиска ≤ 150 мс на 10 000 записей на целевом ПК.

**Повод пересмотреть:** понадобятся поиск с опечатками, ранжирование или русская морфология. Тогда добавить Tantivy как **производный индекс**, который строится из SQLite и перестраивается при потере. Источник данных не меняется.

## Р-3. Надёжность хранилища

3 октября 2026 года.

**Контекст:** в текущем коде найдены места возможной потери или порчи данных (подробно в NP-006 и [architecture.md](architecture.md#известные-ограничения-хранилища)).

**Решение:**

- `PRAGMA synchronous = FULL` вместо `NORMAL`: подтверждённый захват переживает отключение питания. При объёме записей приложения разница в скорости незаметна.
- `busy_timeout` на соединении.
- Последовательные миграции: каждая в своей транзакции, перед каждой — копия `before-vN`.
- Отказ открывать базу с `user_version` новее поддерживаемой. Понятный экран вместо panic при ошибке открытия или миграции.
- Автоматические резервные копии с ротацией и `PRAGMA quick_check` при запуске.
- Начальные данные создаются один раз в миграции.
- Тяжёлые команды (импорт, экспорт, копии, проверка ссылок) — асинхронные, вне главного потока.

**Проверка:** тесты NP-006 на тестовых базах прежних версий, отказ записи посреди миграции, запуск старого бинарника на новой схеме.

## Р-4. Схема заранее готова к синхронизации

3 октября 2026 года.

**Решение:** протокол синхронизации, сервер и провайдера не выбирать. Но уже в первой новой миграции добавить UUID записи рядом с локальным `id`, использовать мягкое удаление (`deleted_at`) как надгробие и единый формат времени UTC. Источник сохранения (`source`) хранить с записью. Точный состав — в NP-005.

**Причина:** иначе к вехе «Синхронизация» понадобится вторая крупная миграция всех библиотек.

## Р-5. Интерфейс: React и Tailwind 4

3 октября 2026 года.

**Решение:** React 19, TypeScript и Vite сохраняются. Новый интерфейс сразу строится на Tailwind 4 (NP-010) без промежуточного переноса стилей «Редакции»: `@tailwindcss/vite`, токены гайдлайна в `@theme`, тёмная тема через `@custom-variant` по `data-theme`. `tailwind.config.js` и autoprefixer удаляются. Списки большой длины виртуализируются. TypeScript-типы IPC генерируются из Rust, ошибки команд имеют машинный код (NP-007).

**Последствия:** Tailwind 4 требует современный движок (Chrome 111+, Safari 16.4+). WebView2 обновляется сам. Для macOS это минимальная версия системы с WKWebView уровня Safari 16.4, для Linux — минимальная версия WebKitGTK. Обе проверяются в NP-008 и при выборе матрицы Linux.

## Р-6. Захват из браузера

3 октября 2026 года.

**Решение:** HTTP v1 на `127.0.0.1:28765` с токеном остаётся основой. После появления установщика исследовать Native Messaging (NP-014): он убирает ручной перенос токена, конфликт порта и позволяет приложению знать о подключённых браузерах. Решение по legacy `/api/add` и ограничениям запросов метаданных — NP-019. Firefox распространяется подписанным XPI без публичного листинга; канал Chrome и Edge в beta выбирается в NP-001.

## Р-7. Ведение backlog

3 октября 2026 года.

**Решение:** задачи живут в GitHub Issues `andmetoo/netamipin`; после публикации источник истины — GitHub, локальный индекс [issues/README.md](issues/README.md) хранит только соответствие ключей и номеров. ## Р-8. Контракт Windows-beta

3 октября 2026 года. Задача NP-001, полный текст — [roadmap.md](roadmap.md#контракт-windows-beta).

**Контекст:** до реализации нужен закрытый объём beta, чтобы исполнители не додумывали платформу, языки и границы.

**Решение:**

- Только Windows 11 x64. Бесплатные обновления безопасности Windows 10 для частных лиц заканчиваются 13 октября 2026 года, ARM64-устройства для проверки нет.
- NSIS на пользователя: установка и обновления без прав администратора, регистрация в `HKCU`. WebView2 через встроенный bootstrapper: установщик не зависит от сети, если WebView2 удалён.
- Chrome и Edge 120+, Firefox — релиз и ESR 140.
- Расширения Chrome и Edge — unlisted в каталогах: обновляются сами и не дают предупреждений режима разработчика. Стоимость — аккаунт разработчика Chrome Web Store и проверка каталогов.
- Интерфейс на английском и русском, английский — исходный и запасной язык, по умолчанию язык системы. Заменяет «язык интерфейса — русский» из [plan.md](plan.md). Документация остаётся на русском.
- Автозапуск включён по умолчанию, старт в трей: иначе ссылки из браузера ждут в очереди до ручного запуска.
- Линия отсечения: NP-026, NP-030, NP-035, NP-036, решение при старте NP-039.

**Последствия:** локализация входит в основу интерфейса (NP-010), каждая UI-задача сдаёт строки на двух языках. macOS и iOS в NP-008 проверяются только сборкой: Mac и iPhone нет.

**Повод пересмотреть:** запросы beta-пользователей на Windows 10 или ARM64; отказ каталога в unlisted-публикации.
