## CI

Workflow `.github/workflows/ci.yml` запускается **только вручную** (Actions → CI → Run workflow) на `windows-2025`: `npm ci`, сборка, Vitest, `cargo test --locked`, Playwright UI без `@visual`. Автоматический запуск на push и PR будет включён позже, ближе к выпуску.

Почему вручную. Репозиторий приватный, минуты Windows-раннеров списываются с коэффициентом ×2. Один прогон двух job занимал около 10 минут на job, то есть ≈ 40 списанных минут на коммит; 3 октября 2026 года четыре отладочных прогона израсходовали около 60 из 3000 минут месяца. При частых коммитах это быстро исчерпывает лимит.

Нативные проверки в CI не включены. На раннере WebView2 Runtime 153 запускает приложение, SQLite и HTTP-сервер работают, но `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` не попадает в командную строку `msedgewebview2.exe`, поэтому порт отладки 9225 не открывается и Playwright не подключается. Локально (WebView2 154) переменная работает. При подключении CI можно передавать порт отладки через `additional_browser_args` окна в тестовой сборке. Также на раннере Tauri создаёт пустую папку профиля по умолчанию (тогда `%LOCALAPPDATA%\com.oddclicks.app`, теперь `app.netami.pin`); данные и профиль WebView2 при этом пишутся только в `.test-data`.

Версии берутся из репозитория: Node.js — `.nvmrc`, Rust — `rust-toolchain.toml`, npm-пакеты и Chromium для Playwright — `package-lock.json`, crates — `Cargo.lock`.

## Локальный запуск

Нужны Node.js из `.nvmrc`, Rust из `rust-toolchain.toml` (rustup установит его сам), Python 3, Microsoft C++ Build Tools и WebView2 Runtime.

**Быстрая проверка перед коммитом** (≈ 15–30 секунд при собранных зависимостях): сборка и типы, Vitest, Rust-тесты.

```powershell
npm run check
```

**Полная проверка** перед PR и при изменении UI, захвата, окна или хранилища. Из чистого клона:

```powershell
npm ci
npm run build
npm test
cd src-tauri
cargo test --locked
cargo build --features custom-protocol --locked
cd ..
npx playwright install chromium
npm run test:ui
npm run test:native
python scripts/smoke-native.py
npm run test:extension
npm run extension:zip
```

Если `python` открывает Microsoft Store, используйте `py scripts/smoke-native.py`. Если после переноса папки проекта `cargo test` не находит файлы в `target\...\tauri-*\out`, выполните `cargo clean -p tauri --manifest-path src-tauri/Cargo.toml`. Переменная окружения `RUSTUP_TOOLCHAIN` переопределяет `rust-toolchain.toml`; для воспроизводимого запуска её не задавайте.

Если браузеры Playwright установлены в нестандартную папку, задайте `PLAYWRIGHT_BROWSERS_PATH`. На машине владельца Chromium из папки по умолчанию `%LOCALAPPDATA%\ms-playwright` не запускается (ошибка side-by-side, `spawn UNKNOWN` в extension smoke), та же сборка из `.cache/playwright` работает; поэтому там используется `.cache/playwright`. Для нативных тестов порты 28765 и 9225 должны быть свободны. Запускайте нативные и extension smoke последовательно: они используют один loopback-порт. Уже работающий сервер тесты не останавливают.

Chrome for Testing запускается с отдельным постоянным профилем и распакованным расширением. Playwright не предоставляет нажатие на кнопку расширения в панели браузера: тестовая копия worker получает ссылку на тот же обработчик `chrome.action.onClicked`, который вызывается тестом. В поставляемом worker такого тестового доступа нет. Хранилище, lifecycle, alarms, разрешения, запросы, страница подключения и SQLite используются настоящие.

Основания: [проверка WebView2](https://playwright.dev/docs/webview2), [проверка расширений](https://playwright.dev/docs/chrome-extensions).

Чтобы повторить проверку релизного бинарника, сначала выполните `cargo build --release --features custom-protocol --locked` в `src-tauri`, затем задайте `$env:NETAMIPIN_TEST_BINARY='src-tauri/target/release/netamipin.exe'` для `test:native` и `test:extension`. Python smoke принимает `--binary src-tauri/target/release/netamipin.exe`. Скрипт Chrome smoke использует встроенный модуль Node.js `node:sqlite`.

## Визуальные эталоны

Эталоны находятся в `tests/ui/visual.spec.ts-snapshots` и проверяются через `toHaveScreenshot` **только локально**. Они зависят от сглаживания шрифтов конкретной машины: 3 октября 2026 года эталоны от 2 октября не совпали на той же машине (около 1 % пикселей, только сглаживание текста), а шрифты раннера отличаются сильнее. Поэтому CI запускает UI с `--grep-invert "@visual"`.

Менять эталоны следует только после просмотра изменения (`npx playwright test --grep "@visual" --update-snapshots`). Эталоны соответствуют «Редакции»; при реализации редизайна их нужно будет пересоздать.

## Ручная приёмка перед распространением

Автотесты не заменяют следующие проверки на пользовательском окружении:

- Масштаб Windows 100% и 125%, перенос окна между мониторами с разным DPI. Настоящий WebView2 в текущем окружении проверен при 150%; браузерные размеры проверены отдельно.
- Нажатие закреплённого значка расширения в обычном установленном Chrome и ручные действия с контекстным меню трея. Обработчик захвата и скрытие/открытие приложения проверены автоматически.
- Ограничения букмарклета на сайтах с CSP и политиками доступа к локальной сети.
- Релизный установщик и обновление ранее установленной версии. Самостоятельные debug/release-бинарники проверены; установщик в рамках этой проверки не собирался.

Фактические скриншоты WebView2 и страницы расширения находятся в `doc/concepts`. При изменении системного масштаба или браузерного профиля результаты ручной проверки следует дописать сюда.
