# Дорожная карта Netami Pin

3 октября 2026 года. Заменяет предыдущую версию (вехи M0–M8 и локальные NP-001–NP-010, в трекере не создавались). Это очередь работы, а не календарь: сроки появятся после первых завершённых задач.

Подробности задач — в GitHub Issues; соответствие ключей `NP-xxx` и номеров — в [issues/README.md](issues/README.md). Пользовательские сценарии — в [scenarios.md](scenarios.md), обоснования — в [decisions.md](decisions.md).

## Принятые решения

Netami Pin — личная библиотека для человека, который сохраняет много ссылок и хочет быстро находить и разбирать накопленное.

- **Первый публичный выпуск — Windows-beta** со всем редизайном итерации 1.
- **Chrome, Edge и Firefox** поддерживаются в первом выпуске. Приложение распространяется установщиком; расширения Chrome и Edge — непубличная публикация в каталогах, Firefox — подписанный XPI без публичного листинга. Окружение, языки и линия отсечения — в [контракте](#контракт-windows-beta).
- Порядок платформ: **Windows → macOS → Linux → Android → iOS**.
- **Синхронизация — после desktop-портов, до мобильных выпусков.**
- Локальное ядро бесплатно и работает без аккаунта. Платные сервисы — позже; окончание подписки не лишает локальной библиотеки и возможности забрать данные.
- Стек сохраняется: Tauri 2, Rust, React, TypeScript; новый интерфейс — **Tailwind 4**. **SQLite — единственное хранилище**, поиск на FTS5 ([Р-2](decisions.md#р-2-sqlite-остаётся-единственным-хранилищем)).
- Офлайн-копии страниц, режим чтения, ИИ-функции, Safari, командные библиотеки и публичные коллекции в план автоматически не входят.

## Контракт Windows-beta

Результат NP-001. Ответы владельца получены 3 октября 2026 года, обоснования — [Р-8](decisions.md#р-8-контракт-windows-beta). Агент не расширяет и не сужает этот объём без решения владельца.

### Окружение

| Вопрос | Решение |
| --- | --- |
| Windows | Только Windows 11, x64. Windows 10 и ARM64 не заявляются и не проверяются, установка на них не блокируется |
| Установка | NSIS на пользователя (`currentUser`), без прав администратора; WebView2 — встроенный bootstrapper (`embedBootstrapper`) |
| Браузеры | Chrome и Edge 120+, Firefox — текущий релиз и ESR 140. Минимумы записаны в манифестах |
| Расширение Chrome и Edge | Непубличная (unlisted) публикация в Chrome Web Store и Edge Add-ons. Firefox — подписанный XPI без листинга ([Р-6](decisions.md#р-6-захват-из-браузера)) |
| Язык | Английский и русский. По умолчанию язык системы, иначе английский; переключатель в настройках. Английский — исходный язык строк; новый язык добавляется файлом перевода без правки кода |
| Автозапуск | Есть, включён по умолчанию, приложение стартует скрытым в трее. Выключается в настройках и галочкой в установщике |
| Устройства для NP-008 | Windows-ПК, виртуальные машины Windows и Linux, Linux, Android. Mac и iPhone нет: macOS и iOS проверяются только сборкой на облачном раннере или откладываются до вехи |

### Линия отсечения

`beta-optional`: NP-026, NP-030, NP-035, NP-036. Список окончательный.

Решение принимается при старте NP-039: если все обязательные задачи закрыты, а `beta-optional` нет, незакрытые переносятся в milestone Windows 1.0. Начатая, но не принятая задача не попадает в beta наполовину: её интерфейс скрыт. Требования [redesign.md](redesign.md) при этом остаются.

Без NP-026 клавиши `1`–`9` в разборе — коллекции в порядке боковой панели. Без NP-030 выделенное переносится панелью массовых действий.

### Правила для всех задач beta

- Строки интерфейса сдаются на английском и русском в той же задаче, что и экран. Макеты нарисованы на русском; английские тексты не должны ломать вёрстку.
- Пункт меню «⋯» появляется вместе с функцией, которую он вызывает; до этого его нет.
- Проверка «на чистой системе» — Windows 11 x64.

**NP-001 → NP-002, NP-003, NP-004, NP-005 → NP-006, NP-007 → NP-009, NP-010, NP-011.**

## Как вести backlog

- **Milestone** — выпуск. **Родительская issue** — сценарий W0–W7 или будущий выпуск. **Дочерняя issue** — задача `NP-xxx` с отдельным проверяемым результатом.
- Метки: тип (`scenario`, `feature`, `decision`, `research`, `release`, `bug`), область (`design`, `library`, `capture`, `data`, `sync`, `distribution`, `infra`, `billing`), платформа (`windows`, `macos`, `linux`, `android`, `ios`), `beta-optional`.
- Доска: `Backlog → Ready → In progress → Review → Done`. Приоритет задают milestone и зависимости.
- Каждая issue содержит ситуацию и результат, текущее состояние, границы, критерии приёмки, проверки, зависимости и изменения документации. Шаблон — `.github/ISSUE_TEMPLATE/task.md`.
- В работу поступают только задачи `Ready`; по умолчанию одна задача реализации одновременно. Дизайн и контракты согласуются до зависимого кода. Общие миграции, `App.tsx` и бинарные макеты — один автор за раз.
- Проверяющий получает требования, diff и результаты тестов. Закрытие issue требует приёмки результата; выпуск отмечается отдельно.
- Ошибки, найденные при приёмке, — отдельные issues с меткой `bug` и ссылкой на задачу.
