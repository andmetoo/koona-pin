## Данные и основной сценарий

- [ ] Сохранить из приложения и расширения, найти, изменить, перезапустить.
- [ ] Повторная доставка не создаёт дубль и не восстанавливает удалённую запись.
- [ ] Импорт не перезаписывает неожиданно пользовательские поля.
- [ ] Миграция с каждой поддерживаемой исходной схемы сохраняет библиотеку.
- [ ] Backup согласован с WAL, восстановление реально проверено на тестовой копии.
- [ ] Недостаток места, отказ записи, прерывание и некорректный импорт не приводят к ложному сообщению об успехе.
- [ ] Корзина, восстановление и массовые операции проверены, если входят в выпуск.

## Расширение и безопасность

- [x] Очередь переживает закрытие приложения/браузера и перезапуск worker — extension smoke в Chrome, Edge, Firefox, ESR 140 и ручные протоколы (NP-017, NP-018).
- [x] Приложение не установлено или не запускается, канал захвата занят, чужой ID расширения, потерянный ответ и повторная передача обработаны — те же проверки и нативные тесты (NP-016…NP-018).
- [ ] Нажатие реальной кнопки расширения проверено в обычном браузере — Chrome, Firefox и ESR 140 проверены владельцем; Edge вручную и неподготовленный пользователь — в сквозной приёмке NP-039.
- [ ] Linux (NP-054; проверка — NP-111, #189): с установленным пакетом каждая заявленная пара браузер × дистрибутив сохраняет ссылку при открытом и закрытом приложении — Chrome, Edge, Chromium из пакетов, Firefox Fedora (`lib64`), Arch, APT Mozilla, Firefox из Snap через портал (разрешение при первом сохранении, перезапуск браузера); браузер из Flatpak и Chromium из Snap — спокойное «Saving isn't available in this browser». Extension smoke в Chrome for Testing и регистрация host с Chromium и Firefox ESR Debian — в задании `check` `linux.yml`.
- [ ] Регистрация host в `HKCU` для Chrome, Edge и Firefox пишется установщиком и удаляется деинсталлятором; сборка установщика — с `--features public-release` (ID разработки не принимается) — установщик NP-037.
- [x] CSP и capabilities соответствуют нужным действиям, права не выданы шире необходимого — NP-019, нативный тест границ.
- [x] Логи и отчёты не содержат личных URL и содержимого библиотеки по умолчанию — NP-019 ([архитектура](architecture.md#границы-приложения)).
- [x] Ограничены схемы URL, размеры, тайм-ауты и нежелательные направления запросов метаданных — NP-019, Rust-тесты `net_guard` и `metadata`.
- [x] Канал захвата открывает только текущий пользователь; длинные и чужие сообщения отклоняются; на `127.0.0.1:28765` никто не слушает — NP-019.

## Пакет, обновление и восстановление

- [ ] Установщик проверен на системе без dev-окружения, включая зависимости WebView, по протоколу [testing.md](testing.md#установщик): установка без прав администратора, без WebView2, повторная установка, удаление с галочкой данных и без, автозапуск после перезагрузки с галочкой и без, захват до первого запуска приложения.
- [ ] Установщик собран `npm run build:installer -- --sign` на компьютере владельца: SimplySign Desktop открыт и вход выполнен кодом из SimplySign Mobile (сессия — 2 часа), в `.env` — `SIGN_CERT_SHA1` (отпечаток сертификата Certum), `signtool` из Windows SDK. `signtool verify /pa /v` проходит для установщика, `koonapin.exe`, `koonapin-host.exe` и `uninstall.exe` в папке установки, издатель — ИП, у подписей есть отметка времени.
- [ ] Технические идентификаторы совпадают с [Р-9](decisions.md#р-9-распространение-windows): `identifier` `app.koona.pin`, `productName` «Koona Pin», EXE `koonapin.exe`, установка в `%LOCALAPPDATA%\Koona Pin`, данные в `%APPDATA%\Koona Pin`. После первого публичного установщика они не меняются: смена ломает обновление.
- [ ] Подпись приложения для выбранного канала настроена и проверена. Для прямой macOS-поставки запланированы signing/notarization по требованиям канала.
- [ ] Если используется Tauri Updater, проверены отдельная подпись обновления и HTTPS-доставка. Подпись установщика ОС не заменяет подпись updater.
- [ ] Приватные ключи находятся вне репозитория по [Р-9](decisions.md#р-9-распространение-windows): ключ updater и пароль — в менеджере паролей и офлайн-копии; восстановление проверено.
- [ ] Обновление предыдущей версии сохраняет данные, настройки и подключение браузера.
- [ ] Пользователь получает понятный результат при недоступной сети и прерванном обновлении.
- [ ] Задокументирована остановка выдачи проблемной версии и выпуск исправления.
- [ ] Старый бинарник не запускается автоматически на несовместимой новой схеме БД. Восстановление backup учитывает изменения пользователя после его создания.
- [ ] Политика удаления приложения и сохранения/удаления личных данных проверена.

Linux-каналы выбраны в [контракте Linux-beta](roadmap.md#контракт-linux-beta): `.deb` и `.rpm` обновляются встроенным updater (пароль через polkit), AUR — pacman, updater в нём выключен. Строки Linux в таблице выше — матрица этого контракта. Mobile обновляется по выбранному мобильному каналу, desktop-updater не считать общей системой для телефона.
