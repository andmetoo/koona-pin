# Архитектура и локальный протокол

## Frontend

`App.tsx` собирает оболочку и сценарии: `components/shell` — боковая панель и панель инструментов, `components/library` — карточка, строка списка, меню закладки, редактор, диалоги и общие поля коллекции и тегов (`Fields.tsx`), `components/settings` — страница настроек, `components/ui` — общие элементы (кнопки, поля, переключатель, сегменты, меню, диалог, уведомления, подсказки клавиш, полоса окна). Стили — Tailwind 4 с токенами гайдлайна в `styles/app.css` ([Р-13](decisions.md#р-13-основа-интерфейса-итерации-1)). Строки — i18next: каталоги `locales/<код>.json`, настройка в `i18n/index.ts`; язык, тема и вид хранятся в `localStorage` (`netamipin.language`, `netamipin.theme`, `netamipin.view`). `useLibrary` отделяет результаты (страницами), справочники, счётчики и события. `components/library/BookmarkList.tsx` показывает сетку и список через [TanStack Virtual](https://tanstack.com/virtual): в DOM только строки у экрана, высоты строк вычисляются, а не измеряются (карточка — превью 16:10 и 73 px текста, строка списка 60 px, заголовок группы 31 px), поэтому прокрутка и метаданные ничего не сдвигают. Конец загруженного рядом — запрос следующей страницы ([Р-15](decisions.md#р-15-сетка-и-список-итерации-1)). `services/library.ts` содержит чистые правила фильтрации и объединения по `id`.

`components/LibraryGate.tsx` показывает приложение только после открытия библиотеки; до этого — «Открываем библиотеку…» (после 300 мс) или экран ошибки по коду `OpenFailure`, тексты — в каталогах (`gate.<код>`).

`services/api.ts` — типизированная граница IPC. Типы контракта генерируются из Rust ([ts-rs](https://crates.io/crates/ts-rs), [Р-12](decisions.md#р-12-typescript-типы-ipc-из-rust-ts-rs)) в `src/bindings` во время `cargo test` и реэкспортируются из `types.ts`; руками там описаны только типы интерфейса (фильтры, вид). Все вызовы идут через `call`: отказ команды превращается в `CommandError` с `code` и `message` (`services/errors.ts`). `describeError` показывает людям понятный текст для `disk_full`, `read_only` и `database_busy`, остальное — сообщением команды. Демо-адаптер использует те же типы и бросает те же ошибки. В Tauri она вызывает Rust-команды, в браузере — независимый `demo.ts` с ключом localStorage `netamipin.demo.v2` и данными из `demoData.ts` (превью — сгенерированные SVG). Превью не обращается к основной базе.

Окно создаётся скрытым и показывается при старте; запуск системой с `--autostart` оставляет его в трее (`autostart.rs`, `tauri-plugin-autostart`). Команды настроек: `get_autostart`, `set_autostart`, `get_data_summary` (папки, число и размер копий, время последней), `back_up_now` (та же проверка и копия, что суточная, вне главного потока).

Поиск задерживается на 150 мс. Номер запроса и версия событий не дают старому ответу заменить новые результаты. Повторные события отбрасываются по ревизии; удаление содержит следующую ревизию без записи. Общие счётчики не зависят от поиска.

Группы списка по дате (`services/dateGroups.ts`): интерфейс передаёт в `since` полночи начала «Сегодня», «Вчера» и «На этой неделе» в формате хранения, первая страница возвращает `since_counts` — сколько совпадений не раньше каждой; так размеры групп верны для всей выборки. В полночь список перечитывается. `getBookmarks(filters, { after })` возвращает `BookmarkPage` — `items`, `total` (все совпадения; только для первой страницы, у следующих `null`) и `next` (курсор `created_at`, `id` или `null`). Следующая страница запрашивается, когда конец списка ближе экрана (`BookmarkList`, NP-012). Ошибка следующей страницы останавливает подгрузку до «Повторить» в плашке ошибки. Смена фильтров сбрасывает курсор, страница старого списка отбрасывается по номеру запроса. Событие для закладки, место которой на ещё не прочитанной странице, её не вставляет, а запоминает новую версию: если страница была запрошена до изменения и пришла со старой строкой, показывается новая версия. Подходит ли изменённая закладка под поиск, решает база (`getBookmarks` с `id`); точные фильтры (`matchesFilters`) проверяются в интерфейсе. `total` после события меняется на месте, если известно, учитывалась ли закладка раньше; иначе запрашивается заново. Правила поиска в TypeScript (`matchesBookmark`) есть только у демо-адаптера.

## Rust и SQLite

`capture.rs` обслуживает IPC-добавление, HTTP и HTML-импорт. Допускаются HTTP/HTTPS с хостом. Дубликаты сравниваются по полному сохранённому URL; существующая запись не меняется. Вставка, теги и квитанция выполняются в одной транзакции; успех возвращается после commit.

`db.rs` содержит запросы. Время везде UTC с миллисекундами (`YYYY-MM-DDTHH:MM:SS.sssZ`), у закладок, коллекций и тегов есть `uid` (UUIDv7). Захват пишет `source` и оставляет `triaged_at` пустым (во «Входящих»), импорт пишет `import` и время разбора. Удаление закладки и коллекции оставляет запись в `tombstones`. `capture_receipts` намеренно не имеет внешнего ключа на закладку: квитанция переживает удаление.

Команды возвращают `Result<_, CommandError>` (`error.rs`): `{ "code": "...", "message": "..." }`, как ошибки HTTP v1. Код ошибки базы выводится из кода SQLite: `SQLITE_FULL` → `disk_full`, занятость → `database_busy`, `query_only` после повреждения → `read_only`, нарушение уникальности → `conflict`, внешнего ключа или нет строки → `not_found`, другие ограничения → `invalid_request`, прочее → `database_error`; ошибки вне базы — `internal`. Пока библиотека не открыта, Tauri сам отклоняет команды с базой текстом, интерфейс видит их как `internal`.

Все команды с базой асинхронные: `commands::blocking` выполняет работу через `spawn_blocking`, поэтому главный поток (окно, трей) никогда не ждёт блокировку базы. Синхронными остались команды без базы. Обработчик закрытия окна читает настройку трея из `AtomicBool`. HTML-импорт разбирает файл вне блокировки и сохраняет все ссылки одной транзакцией.

### Открытие библиотеки

`library_state.rs` открывает библиотеку в фоновом потоке, окно появляется сразу. Интерфейс спрашивает `get_library_status` (`opening`, `ready` с `damaged` и `moved_aside`, `failed` с `OpenFailure`) и слушает событие `library-status`. Пока библиотека не открыта, `DbState` не зарегистрирован, команды с базой отвечают ошибкой, HTTP-сервер не запущен. `retry_library` повторяет открытие после ошибки, `reveal_library_place` открывает папку с данными, копиями или копию перед миграцией (пути знает только Rust), `quit_app` закрывает приложение.

`library.rs` по шагам:

1. Существующий файл сначала открывается **только для чтения**. Чужой `application_id`, или пустой `application_id` у файла без таблицы `bookmarks` → `DB_FOREIGN`; `user_version` больше поддерживаемой → `DB_NEWER_SCHEMA`; файл не SQLite → `DB_NOT_DATABASE`; занят → `DB_LOCKED`. Перед миграцией существующей библиотеки — `PRAGMA quick_check`, ошибка → `DB_CORRUPT`. Во всех этих случаях файл не меняется ни на байт.
2. Файл без `application_id` с таблицей `bookmarks` — библиотека сборки до схемы 1. Он вместе с `-wal` и `-shm` переименовывается в `netamipin.old-<дата-время>.db`, создаётся новая библиотека.
3. Соединение: WAL, `foreign_keys = ON`, `synchronous = FULL`, `busy_timeout` 5 с.
4. Миграции `migrations.rs` через [rusqlite_migration](https://crates.io/crates/rusqlite_migration) 1.3: номер схемы — `user_version`, все ожидающие шаги и новый `user_version` в одной транзакции. Перед миграцией существующей библиотеки — копия `backups/netamipin.before-vN.db` (`VACUUM INTO`), хранятся две последние. Сбой копии → `BACKUP_FAILED`, сбой миграции → откат и `MIGRATION_FAILED` с путём к копии.

Схема 2 (NP-011) добавляет поисковый индекс `bookmarks_search` (FTS5, `tokenize='trigram'`, `content=''`, `contentless_delete=1`): заголовок, URL, домен, описание, заметка и теги. Текст в индексе не хранится, только индекс. Строки индекса пишут триггеры на `bookmarks`, `bookmark_tags` и переименование тегов — в той же транзакции, что и запись; источник строк — представление `bookmarks_search_source`, где «ё» заменена на «е». Миграция строит индекс для существующей библиотеки (100 000 записей — около 1,2 с в release) и меняет индекс сортировки на `idx_bookmarks_order (created_at, id)`. Библиотеку схемы 2 сборки со схемой 1 не открывают (`DB_NEWER_SCHEMA`).

Поиск (`db::get_bookmarks`, [Р-14](decisions.md#р-14-поиск-на-fts5-trigram)): запрос делится на слова, каждое должно найтись в любом поле, порядок не важен. Слова от трёх символов идут в индекс как фразы `"слово"` (синтаксис FTS5 в запросе не работает) с «ё» → «е»; регистр сворачивает токенизатор trigram — так же, как он свернул текст. Слова из одного-двух символов индекс не находит: их проверяет функция `np_contains` (регистрируется на соединении в `library::configure`) — по строкам, оставленным индексом, или одним проходом по таблице, если длинных слов нет; теги проверяются один раз каждый. Фильтры коллекции, тега, домена, избранного и `id` применяются в том же запросе. Общее число и `since_counts` (размеры групп по дате) считаются одним проходом и только для первой страницы. Страница — `ORDER BY created_at DESC, id DESC LIMIT`, курсор — `(created_at, id) < (?, ?)`, теги страницы — одним запросом. `rebuild_search_index` (Настройки → Данные) строит индекс заново одной транзакцией и выдаёт `library-invalidated`.

Схема 1 создаётся одним шагом и сразу содержит всё из [Р-10](decisions.md#р-10-модель-данных-и-миграции): `uid`, `source` с `CHECK`, `triaged_at`, `deleted_at`, `tombstones`, `application_id = 0x4E50494E`; начальные коллекции и токен создаются в этом же шаге один раз. Выпущенный шаг не меняется; изменение схемы — новый шаг. Шаг, который пересоздаёт таблицу, должен сам отключить внешние ключи до транзакции: внутри неё `PRAGMA foreign_keys` не действует, а удаление родительской таблицы с включёнными ключами удалит дочерние строки.

После открытия фоновый поток раз в час вызывает `library::maintain` на отдельном соединении только для чтения: при запуске всегда `quick_check`, затем копия `backups/netamipin.auto-<дата-время>.db`, если последней больше суток; хранятся 7 ежедневных и 4 еженедельных. Проверка идёт **до** копии: повреждённая библиотека не попадает в копии и не вытесняет исправные. При повреждении основное соединение получает `PRAGMA query_only`, статус становится `ready` с `damaged: true`, интерфейс показывает плашку.

Метаданные запрашиваются отдельно через Tauri async runtime. UPDATE по исходному `id` не создаёт удалённую запись. Заголовок применяется только при совпадении исходной ревизии: правка после запуска задачи сохраняет пользовательский заголовок.

Событие `bookmark-changed`: `BookmarkChange` — `{ kind: "created" | "updated" | "deleted", id, revision, bookmark }`. Массовая операция выдаёт `library-invalidated`. Patch коллекции: `{ action: "keep" }`, `{ action: "clear" }`, `{ action: "set", id: 1 }`.

### Известные ограничения хранилища

Состояние кода после NP-011 (3 октября 2026 года).

- Удаление жёсткое (с записью в `tombstones`); корзина и «Входящие» есть в схеме, но не в запросах и интерфейсе — NP-021, NP-022. `bookmarks.url` уникален.
- Поиск без опечаток, морфологии и ранжирования; порядок результатов — по дате сохранения ([Р-2](decisions.md#р-2-sqlite-остаётся-единственным-хранилищем)). Запрос из одних слов в один-два символа на 100 000 записей проверяет всю таблицу: до 165 мс ([замер](testing.md#замер-поиска)).
- Рассинхронизацию индекса с библиотекой приложение само не обнаруживает: её исправляет кнопка «Перестроить» в настройках.
- Восстановления из копии в интерфейсе нет (NP-034): повреждённую библиотеку заменяют копией вручную при закрытом приложении.
- Сборки до схемы 1 проверки `application_id` не имеют: такая сборка откроет библиотеку схемы 1 и будет писать в неё. Публично они не выпускались ([Р-11](decisions.md#р-11-чистая-схема-1-вместо-переноса-данных)).
- Повреждение, возникшее во время работы, обнаруживается при следующей проверке: при запуске или перед суточной копией.

У строки окна есть разрешения для сворачивания, разворачивания, закрытия и перетаскивания; последнее нужно отдельно для `data-tauri-drag-region` согласно [документации Tauri](https://v2.tauri.app/learn/window-customization/).

## HTTP v1

Адрес: `http://127.0.0.1:28765`. Токен из двух случайных UUID хранится в локальных настройках и переносится пользователем в Chrome. Захват требует `Authorization: Bearer <token>`.

```http
POST /api/v1/capture
Content-Type: application/json
Authorization: Bearer <локальный токен>

{"request_id":"постоянный UUID захвата","url":"https://example.com/article","title":"Название страницы"}
```

```json
{ "bookmark_id": 42, "outcome": "created" }
```

Повтор URL с новым request_id возвращает `existing`. Повтор исходного request_id возвращает квитанцию, даже если закладка удалена; он не вставляет запись снова. Один request_id с другим URL возвращает конфликт. Максимум URL — 8192 символа, request_id — 128 символов, тело HTTP — 64 KiB.

| Статус | Код                   | Причина                                             |
| ------ | --------------------- | --------------------------------------------------- |
| 200    | —                     | Подтверждённая транзакция, `created` или `existing` |
| 400    | `invalid_request`     | Неверные данные                                     |
| 401    | `unauthorized`        | Нет токена или токен не подходит                    |
| 404    | `not_found`           | Неизвестный endpoint                                |
| 405    | `method_not_allowed`  | Неверный метод                                      |
| 409    | `request_id_conflict` | Идентификатор относится к другому URL               |
| 500    | `database_error`      | Запись не подтверждена                              |

Ошибка имеет `code` и `message`. `GET /api/health` возвращает `{ "status":"ok", "name":"Netami Pin", "protocol":1 }`; расширение проверяет `name`. Без токена health доступен для диагностики; переданный Authorization проверяется. IPC `get_server_status` сообщает фактический результат привязки порта.

Необязательное поле `source` в теле v1 (`chrome`, `edge`, `firefox`) сохраняется как источник закладки; другое значение или его отсутствие — `extension` (поле начнёт отправлять расширение в NP-016). `/api/add` пишет `bookmarklet`, IPC — `app`, HTML-импорт — `import`. В библиотеке только для чтения (повреждение) захват отвечает `500 database_error`, и ссылка остаётся в очереди расширения.

Совместимый `/api/add` принимает GET/POST с query-параметрами либо POST с JSON, без токена. Это ограничение совместимости: токен защищает новый v1 API, старый канал допускает локальное добавление ссылок.

## Расширение

MV3 worker выполняет запросы. `queue.js` последовательно обрабатывает добавление, отправку, повтор и удаление через одну цепочку операций. `chrome.storage.local` хранит URL, название, request_id, время и ошибку. Подтверждение требует целый `bookmark_id` и известный `outcome`.

`activeTab` даёт доступ к выбранной странице после нажатия; `storage` хранит очередь; `alarms` возобновляет доставку. Host permission относится к `127.0.0.1` (Chrome match patterns не ограничивают порт), CSP и код ограничивают сервер портом 28765. Content scripts и удалённый код отсутствуют.

Основания: [сетевые запросы](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests), [жизненный цикл worker](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [chrome.alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms).

Для тестов `NETAMIPIN_DATA_DIR` меняет каталог SQLite, `WEBVIEW2_USER_DATA_FOLDER` — профиль WebView2.

## Прежнее имя OddClicks

Данные OddClicks и тестовых сборок до схемы 1 не переносятся ([Р-11](decisions.md#р-11-чистая-схема-1-вместо-переноса-данных)). Старое имя осталось только в одном месте: если OddClicks запущена и держит порт 28765, сервер Netami Pin распознаёт её по `/api/health` с `"app":"OddClicks"` без поля `name`, а интерфейс показывает предупреждение — ссылки из браузера уйдут в старую библиотеку, пока OddClicks не закрыта. Архивные концепты (`src/concepts`, `concept.html`) и исторические документы не переименовывались.
